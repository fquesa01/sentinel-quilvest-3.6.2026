# Sentinel Counsel LLP

## Overview
Sentinel Counsel LLP is an enterprise-grade AI-powered platform for comprehensive compliance monitoring and management. It provides real-time surveillance, AI-driven detection, robust case management, extensive regulatory knowledge bases, and advanced analytics. The platform aims to minimize compliance risk for large organizations by supporting adherence to regulations like FCPA, Federal Antitrust, SOX, and BSA/AML. Key capabilities include advanced document search, an AI interview system, chronological event tracking, an anonymous whistleblower portal, and a crisis response module, offering a smart, centralized solution for navigating complex regulatory landscapes, enabling proactive compliance and effective risk mitigation.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture

### UI/UX Decisions
The frontend uses React 18, TypeScript, Vite, Wouter, and TanStack Query. Styling is based on Shadcn/ui (Radix UI) and Tailwind CSS, adhering to Carbon Design System patterns. Features include hierarchical sidebar navigation, role-based access control, customizable column visibility, 7 themes, advanced document search interfaces, collaborative highlighting and commenting, and specialized chat message review. Progressive reveal animations are applied using utility classes.

### Technical Implementations
The backend uses Node.js, Express.js, and TypeScript, providing RESTful API endpoints. Authentication leverages Replit Auth (OpenID Connect with Passport.js), Microsoft OAuth 365, Google OAuth 2.0 (passport-google-oauth20), and email/password login (bcryptjs hashing), including automatic account linking and role-based access control. Google OAuth requires GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET environment secrets. Data persistence is managed by Supabase PostgreSQL with Drizzle ORM. Connection configured via `SUPABASE_DATABASE_URL` secret (falls back to `DATABASE_URL` if not set). The `server/db.ts` module parses connection strings with special characters in passwords by extracting individual fields (user, password, host, port, database) rather than passing raw URLs. Session store uses the shared pool from `server/db.ts`. Schema migrations use `pg_dump --schema-only` from source DB then `psql` import (drizzle-kit push hangs with Supabase). Post-merge scripts (`scripts/post-merge.sh`) use `$SUPABASE_DATABASE_URL` with `$DATABASE_URL` fallback. The system supports secure file uploads with automatic text extraction, a comprehensive email ingestion module, and an extensible Third-Party Connector Ingestion Framework.

#### Organizations & Multi-Tenancy
The app supports a multi-tenant organization model. Users have a `userType` field (`individual` or `corporate`). Corporate users belong to an organization via `organization_members` join table. Users in the same organization automatically see each other's deals, data rooms, and form templates. Admin users see everything regardless. Schema: `organizations` table (id, name, description, metadata), `organization_members` (organization_id, user_id), plus `user_type` and `password_hash` columns on `users`. API routes: `/api/organizations` (CRUD), `/api/organizations/:id/members` (add/remove), `/api/auth/login` (email+password). Admin UI: User Management page has Users and Organizations tabs.

### External Agent API Access (API Keys)
- **API Keys Management:** Admins can create, view, and revoke API keys from `/api-keys` page (sidebar: Administration > API Keys). Each key has a display name, permission scopes, and configurable rate limits.
- **Permission Scopes:** `deals:read`, `deals:write`, `documents:read`, `documents:write`, `cases:read`, `cases:write`, `analysis:trigger`, `communications:read`.
- **Authentication:** External agents authenticate via `Authorization: Bearer <key>` or `X-API-Key` header. Keys are hashed (SHA-256) and stored securely; raw key shown only at creation.
- **External API Surface:** All external endpoints under `/api/v1/external/` namespace: deals CRUD, cases listing, documents listing, communications, AI analysis triggers, health check. Consistent JSON responses with pagination (`page`, `limit`, `total`, `totalPages`).
- **Rate Limiting:** In-memory sliding window per key (configurable requests/minute, default 60). Returns 429 with retry info when exceeded.
- **Audit Logging:** Every API key request is logged to `api_key_audit_logs` table with method, path, status code, IP, user agent, timestamp. Viewable per-key or globally in the UI.
- **Schema:** `api_keys` table (id, display_name, key_hash, key_prefix, user_id, scopes, rate_limit_per_minute, is_active, last_used_at, expires_at, revoked_at, created_at) and `api_key_audit_logs` table.
